# مدیریت مهمانی هالووین 🎃

سایت فارسی و واکنش‌گرا برای فهرست مهمان‌ها، زیرمجموعه‌ها و میزبان‌ها؛ مناسب انتشار روی GitHub Pages با دیتابیس و ورود مدیر در Supabase.

## قابلیت‌ها

- رابط فارسی راست‌چین با فونت Vazirmatn
- فهرست عمومی فقط شامل نام‌ها، ساختار زیرمجموعه‌ها و تعداد افراد
- مبلغ پرداختی و گزارش مالی فقط برای کاربر واردشده
- مدیریت مهمان اصلی، زیرمجموعه‌ها و میزبان‌ها
- محاسبه خودکار مجموع پرداخت مهمان‌ها، میزبان‌ها و کل دریافتی
- اعداد فارسی و نمایش مبلغ به تومان
- انیمیشن تعاملی کدو و اسکلت
- طراحی واکنش‌گرا برای موبایل و دسکتاپ

## نکته امنیتی مهم

این پروژه برای بخش عمومی از viewهای `guests_public` و `hosts_public` استفاده می‌کند که ستون مبلغ را اصلاً نمایش نمی‌دهند. جدول‌های اصلی فقط برای کاربران احراز هویت‌شده قابل دسترسی هستند. این نمونه فرض می‌کند تنها حساب احراز هویت‌شده، حساب مدیر است؛ بنابراین **ثبت‌نام عمومی را در Supabase غیرفعال کنید و حساب‌های اضافی نسازید**. اگر چند مدیر لازم دارید، سیاست‌ها را به نقش اختصاصی مدیر محدود کنید.

هرگز کلید `service_role`، رمز مدیر یا اطلاعات محرمانه را در `config.js` یا هر فایل فرانت‌اند قرار ندهید. کلید `anon`/`publishable` برای استفاده در مرورگر طراحی شده و امنیت دسترسی را باید RLS تأمین کند.

## بخش ۱: ساخت پروژه Supabase

1. وارد [Supabase](https://supabase.com/) شوید و یک پروژه جدید بسازید.
2. یک رمز قوی برای دیتابیس انتخاب و در جای امن نگهداری کنید.
3. از منوی **SQL Editor** یک query جدید بسازید.
4. تمام محتوای فایل `supabase.sql` را کپی کنید و اجرا کنید.
5. به **Authentication → Providers → Email** بروید و ورود با ایمیل/رمز عبور را فعال نگه دارید.
6. از **Authentication → Users** حساب مدیر را با ایمیل و رمز قوی بسازید. اگر گزینه ثبت‌نام عمومی فعال است، آن را در تنظیمات Auth غیرفعال کنید. مدیر از صفحه ورود سایت با ایمیل و رمز وارد می‌شود.
7. در **Project Settings → API** آدرس پروژه و کلید `anon` یا `publishable` را بردارید. کلید `service_role` را استفاده نکنید.

### درباره سطح دسترسی

- مهمان‌ها و میزبان‌ها برای عموم از viewهای محدود قابل مشاهده‌اند.
- مبلغ‌ها در جدول اصلی هستند و از viewهای عمومی حذف شده‌اند.
- عملیات نوشتن و خواندن جدول‌های اصلی به کاربران واردشده محدود شده است.
- با غیرفعال‌بودن ثبت‌نام عمومی و ساختن فقط حساب مدیر، پنل مدیریتی محدود می‌ماند.

## بخش ۲: تنظیم فایل اتصال

فایل `config.js` را باز کنید و این دو مقدار را جایگزین کنید:

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY"
};
```

- `SUPABASE_URL`: آدرس پروژه Supabase
- `SUPABASE_ANON_KEY`: کلید عمومی `anon` یا `publishable`

این کلید عمومی است؛ با این حال سیاست‌های دیتابیس و RLS باید فعال بمانند. رمز مدیر و کلید `service_role` را هرگز در سایت نگذارید.

## بخش ۳: انتشار روی GitHub Pages

1. در GitHub یک repository جدید بسازید، مثلاً `halloween-party`.
2. فایل‌های این پوشه را در ریشه repository قرار دهید: `index.html`, `style.css`, `app.js`, `config.js`, `supabase.sql`, `README-FA.md`.
3. فایل‌ها را commit کنید.
4. در repository به **Settings → Pages** بروید.
5. در بخش **Build and deployment**، گزینه **Deploy from a branch** را انتخاب کنید.
6. Branch را روی `main` و پوشه را روی `/(root)` بگذارید و Save کنید.
7. پس از پایان انتشار، GitHub یک آدرس شبیه `https://USERNAME.github.io/halloween-party/` می‌دهد.
8. آدرس را باز کنید و تست کنید که نام‌ها برای بازدیدکننده قابل مشاهده باشند.

## بخش ۴: تست امنیت و عملکرد

1. در حالت ناشناس مرورگر آدرس سایت را باز کنید؛ باید نام‌ها و تعدادها دیده شوند، اما هیچ مبلغی نمایش داده نشود.
2. روی «ورود ادمین» بزنید و با ایمیل و رمز مدیر وارد شوید.
3. یک مهمان اصلی بسازید و سپس از گزینه «زیرمجموعه» فرد دیگری اضافه کنید.
4. یک میزبان اضافه کنید.
5. مبالغ را وارد کنید و گزارش مالی را بررسی کنید.
6. خارج شوید و مطمئن شوید مبلغ‌ها دوباره پنهان می‌شوند.
7. در Supabase از API/SQL یا ابزارهای تست، بررسی کنید که کاربر ناشناس نتواند از جدول‌های اصلی `guests` و `hosts` مقدار `amount_toman` را بخواند.

## نکات و محدودیت‌های نسخه اول

- مبلغ هر فرد به صورت عدد صحیح تومان ذخیره می‌شود؛ هنگام ورود اعداد فارسی و انگلیسی پذیرفته می‌شوند.
- حذف مهمان اصلی، زیرمجموعه‌هایش را نیز حذف می‌کند.
- نسخه فعلی میزبان‌ها را در فهرست مستقل مدیریت می‌کند.
- سایت برای اتصال اولیه به اینترنت نیاز دارد (Supabase و فونت Google Fonts از CDN بارگیری می‌شوند).
- در صورت نیاز به چند مدیر با سطح دسترسی‌های متفاوت، باید نقش مدیر به‌صورت جداگانه در دیتابیس تعریف شود؛ صرفاً هر کاربر authenticated را مدیر فرض نکنید.
- بعد از تغییر SQL، در صورت خطای API، چند لحظه صبر کنید تا schema cache تازه شود یا از SQL Editor دستور `notify pgrst, 'reload schema';` را اجرا کنید.

## فایل‌ها

- `index.html`: ساختار صفحه
- `style.css`: ظاهر، رنگ‌ها و واکنش‌گرایی
- `app.js`: منطق فهرست، احراز هویت و محاسبه پرداخت‌ها
- `config.js`: تنظیمات عمومی اتصال به Supabase
- `supabase.sql`: ساخت جدول‌ها، viewهای عمومی و سیاست‌های دسترسی

## تغییرات فهرست شرکت‌کنندگان
- فهرست مهمان‌ها و میزبان‌های قبلی در صفحه در یک بخش «شرکت‌کنندگان» نمایش داده می‌شود.
- شرکت‌کنندگان جدید در جدول `guests` ذخیره می‌شوند؛ برای نفر اصلی، والد انتخاب نمی‌شود و برای زیرمجموعه، نفر اصلی از فهرست انتخاب می‌شود.
- رکوردهای میزبان قدیمی پاک یا منتقل نمی‌شوند؛ آن‌ها همچنان در فهرست یکپارچه و گزارش مالی ادمین دیده می‌شوند و امکان ویرایش/حذف دارند.
- برای این تغییر نیازی به اجرای دوباره `supabase.sql` نیست. فایل `config.js` موجود خودتان را حفظ کنید و آن را با نسخه ZIP جایگزین نکنید، چون حاوی تنظیمات اتصال پروژه شماست.
